## <u>Tidyverse:</u>

This markdown file explores the tidyverse library in R: The tidyverse
library has these packages each for a specific purpose: tidyr, dplyr,
stringr, lubridate, ggplot2, forcast, tibble,and purr. We shall explore
all these packages in the tidyverse library: The single most syntatic
operator in the tidyverse is the pipe operatior( \|\> or %\>%)

### <u>summarise() and group_by() – Aggregation</u>

The combination of group_by() and summarise() is the cornerstone of
statistical aggregation in the tidyverse. Always ungroup() after grouped
operations to prevent downstream bugs. The .drop argument determines
whether to ignore groups combination or simply groups without data.

``` r
# let's get some groupings and summaries from the insurance data
insurance |> 
  select(smoker, charges) |> 
  group_by(smoker,.drop = FALSE) |> 
  summarise(
    n = n(),
    Mean_charge = mean(charges,na.rm = TRUE),
    Std_charge = sd(charges,na.rm = TRUE),
    Median_charge = median(charges, na.rm = TRUE),
    .groups = "drop"  #automatically ungroups : best practice
  )
```

#### Multiple Grouping : Let’s group by smoker and sex

In multiple groupings you specify whether the first group should be
used, last group or both, or drop both groups. we use the .groups
argument in the summarise function.

The .drop is used to tell R whether to show groups with empty values or
omit them entirely. Used in the group_by function.

``` r
insurance |> 
  select(smoker,sex,charges) |> 
  group_by(smoker,sex ,.drop = FALSE) |> 
  summarise(
    n = n(),
    Mean_charge = mean(charges,na.rm = TRUE),
    Std_charge = sd(charges,na.rm = TRUE),
    Median_charge = median(charges, na.rm = TRUE),
```

Row_number : Ranks without ties, when there is a tie, the first number
is arbitrary assigned the lowest number and the next tie have the next
unique number. By default row_number ranks in ascending order that is
smaller number ranked first. So to make high numbers rank first, you
have to rearrange with descending, desc().

**NB: Percent rank can be ascending or descending:**

if ascending it is interpreted as what percentage of people did the
number x, or student x_stud beat in score. In descending, it is
interpreted as what percentage of people beat the number x or stud_x in
score.

``` r
scores |> 
  mutate(
    row_rank = row_number(desc(score)), # no ties
    score_main = min_rank(desc(score)), # ties are given same number and skips next

    percen_rank = percent_rank(desc(score)) # rank
```

#### Lag and Lead

- **`lag()`** → pulls the **previous** row’s value into the current row
- **`lead()`** → pulls the **next** row’s value into the current row
- You can use default = 0 to modify the default NA value where no value
  exit after lead or lag

``` r
# let's work on some lead and lag examples
#-----------------------------------------------------
df <- tibble(
  month = c("Jan", "Feb", "Mar", "Apr", "May"),
  sales = c(100, 120, 90, 150, 130)
)

df %>%
  mutate(
    prev_sales = lag(sales, n=1),     # what did we sell last month?
    next_sales = lead(sales, n =1),    # what will we sell next month?
    change = sales - lag(sales)  # calculating change
  )
```

### The Simple Rule

Sometimes all the columns to pivot do not hold the same kind of value or
information: In that case for the names_to argument , use .value as part
of the names. The position of the .value in names_to depends on the
column pattern. for instance in the example below, the values are
contained in the first part of the column name pattern and the second
part actually tells time.

NB: You can also use name_sep argument instead of name_pattern

| Situation | What to use |
|----|----|
| All pivoted columns hold the **same kind of value** | `values_to = "some_name"` |
| Pivoted columns hold **different kinds of values**, distinguished by part of the column name | `.value` in `names_to` |

``` r
# let's work on this 

multip<- multi |>
```
